# dev-infra

여러 프로젝트에 공통으로 쓰는 에이전트 개발 인프라의 정본.

실제 멀티서비스·다중 에이전트 운영 환경에서 검증된 패턴을 일반화한 것이다.
원칙과 패턴은 여기에 있고, 프로젝트 고유 값(도메인, 포트, 서비스 목록)은 각
프로젝트의 프로파일 파일에 있다. **여기를 고치면 모든 프로젝트가 따라오고,
프로파일을 고치면 그 프로젝트만 바뀐다.**

```
infra/                      머신 공유 인프라 — MySQL·PG·Redis(+Kafka·Mongo·…) 한 벌.
                            엔진은 머신에 하나, 분리는 database·계정·프리픽스로
skills/                     레포를 가리지 않는 스킬 정본
  shared-local-runtime/     병렬 에이전트를 위한 공유 로컬 런타임 운영
```

## 프로젝트에 적용하기

1. 스킬의 `references/runtime-profile.md`를 읽고 프로젝트 루트에
   `.agents/runtime-profile.yml`을 작성한다 — 쓰는 엔진을 `data.engines`에
   선언한다.
2. `devinfra setup <프로젝트 루트>` — yml을 읽어 필요한 엔진만 기동하고
   database를 프로비저닝한다. 멱등이라 몇 번을 돌려도 안전하다.

CLI 설치는 이 체크아웃에서 한 번: `npm install && npm link`. 그 뒤에는
어디서든 `devinfra setup | up | status | provision` 을 쓴다 (링크 없이
`node infra/bin/cli.mjs …` 로도 동작한다). 내리는 명령은 일부러 없다 —
여러 프로젝트가 살고 있는 인프라의 중지는 사람이 직접 결정한다.
3. 스킬을 전역 스킬 디렉토리(`~/.claude/skills/` 등)에 두거나, 쓰는 에이전트
   도구의 스킬 공유 채널로 배포한다.
4. 프로젝트 안에서는 정본을 도구 중립 경로(`.agents/skills/`)에 두고, 도구별
   디렉토리(`.claude/skills/` 등)에는 symlink 어댑터만 둔다 — 본문을 어댑터에
   복사하지 않는다.

## 원칙

- 패턴과 값을 한 파일에 섞지 않는다. 섞는 순간 두 번째 프로젝트에서 갈라진다.
- 스킬 본문에 특정 프로젝트의 도메인·포트·서비스 이름을 적지 않는다.
  예시가 필요하면 `examples/`의 프로파일 인스턴스를 가리킨다.
